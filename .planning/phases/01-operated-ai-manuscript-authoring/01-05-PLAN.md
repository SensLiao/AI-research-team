## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| machine -> PhD-Research-OS | Vault material is untrusted read-by-reference input; this phase has no vault writer or promotion authority. |
| worker -> scheduler/run store | Worker bundles cross a least-privilege boundary and become visible only after schema, scope, dependency-receipt, and hash checks. |
| manuscript source -> filesystem/TeX process | Generated TeX and asset paths are untrusted until run-root, symlink/reparse, directive, and subprocess checks pass. |
| scholarly provider -> persisted artifacts | Provider URLs and errors may contain secrets and must be sanitized before ledger, build, or director-facing persistence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-VLT | Tampering / Elevation | vault and run paths | high | mitigate | Worker scopes prevent asset overwrite, cross-section shared writes, undeclared input reads, and reviewer contamination; all proposed outputs stay hash-bound candidates; preserve bounded tools/recall.py reads, run-owned writes, unchanged-vault assertions, and no promotion imports. |
| T-05-SEC | Information Disclosure | scholarly URLs, errors, logs, TeX, packets | high | mitigate | Persist only sanitized provider/path/status/request facts and run sentinel-secret scans before any artifact becomes durable. |
| T-05-TEX | Elevation / Denial of Service | TeX input and compiler subprocess | high | mitigate | Fence paths including symlink/reparse targets, reject unsafe TeX directives, use fixed argv with shell disabled and bounded time/output. |
